# Lean Canvas

## Purpose
Use this skill to test a startup idea quickly and clearly.

## When to use
- The user names Lean Canvas explicitly.
- The task matches: test a startup idea quickly and clearly.

## Before you start
Confirm or ask for: the company/market/context, the decision being made, the time horizon, and any available data. If data is missing, state assumptions explicitly and label them.

## Process
1. Fill: Problem (top 3), Customer Segments, Unique Value Proposition, Solution, Channels, Revenue Streams, Cost Structure, Key Metrics, Unfair Advantage.
2. Rank risks: which assumption kills the idea if wrong?
3. Design the cheapest experiment per top risk.
4. Iterate the canvas after results.

## Output format
Nine-block canvas, risk ranking, and experiment plan.
Lead with the answer or key insight first, then supporting detail. Keep the structure MECE and quantify wherever possible.

## Common pitfalls
Starting with the solution instead of the problem.

## Quality checklist
- [ ] Conclusions are evidence-based and sources or assumptions are stated.
- [ ] Output ends with clear, prioritized recommendations ("so what").
- [ ] Categories do not overlap and nothing material is missing.
